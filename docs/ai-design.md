# DiffBeacon AI Architecture & Guardrails Specification

**Version:** 1.0.0  
**Status:** Approved  
**Date:** October 2026  

---

## 1. Core Philosophy: The Zero-Fabrication Mandate

In DiffBeacon, **the AI layer is strictly downstream of deterministic static analysis**.

### Prohibited AI Behaviors
The AI must **never**:
1. Invent a source file path, function name, class, or line number.
2. Invent a dependency edge between modules that does not exist in the verified AST graph.
3. Assert that a test has executed when it has not.
4. Conflate a static hypothesis with a runtime certainty.
5. Manufacture a confident explanation when static facts are insufficient.

---

## 2. Bounded Context Package

When invoking an LLM for scenario interpretation or delta synthesis, the system provides **only** a strictly bounded context package containing:

```json
{
  "scenario_question": "What happens if a request omits department_id now?",
  "changed_symbol": {
    "qualified_name": "api.serializers.EmployeeCreateSerializer",
    "file_path": "beaconworks/api/serializers.py",
    "base_lines": [24, 30],
    "head_lines": [25, 33]
  },
  "source_excerpts": {
    "base": "class EmployeeCreateSerializer(serializers.ModelSerializer):\n    department_id = serializers.PrimaryKeyRelatedField(required=True, queryset=Department.objects.all())",
    "head": "class EmployeeCreateSerializer(serializers.ModelSerializer):\n    department_id = serializers.PrimaryKeyRelatedField(required=False, allow_null=True, queryset=Department.objects.all())"
  },
  "candidate_paths": {
    "base": [
      { "symbol": "api.views.EmployeeViewSet.create", "file": "beaconworks/api/views.py", "line": 48 },
      { "symbol": "api.serializers.EmployeeCreateSerializer.is_valid", "file": "beaconworks/api/serializers.py", "line": 32 }
    ],
    "head": [
      { "symbol": "api.views.EmployeeViewSet.create", "file": "beaconworks/api/views.py", "line": 48 },
      { "symbol": "api.serializers.EmployeeCreateSerializer.is_valid", "file": "beaconworks/api/serializers.py", "line": 35 },
      { "symbol": "api.services.employee.assign_default_department", "file": "beaconworks/services/employee.py", "line": 19 }
    ]
  },
  "known_unknowns": [
    { "type": "dynamic_call", "file": "beaconworks/services/notifications.py", "line": 68 }
  ]
}
```

The model does not receive the raw repository or unstructured diff streams. It reasons strictly over the validated graph paths and source excerpts.

## 3. Pluggable Provider Interface

The AI integration lives behind an abstract provider protocol:

```python
class LLMProvider(ABC):
    @abstractmethod
    def synthesize_scenario(
        self,
        package: BoundedContextPackage
    ) -> ScenarioSynthesisResult:
        """Synthesize scenario trace and verification recommendations."""
        pass
```

### Supported Implementations:
1. **`DeterministicMockProvider` (Default / Demo):**
   - Returns deterministic, fixture-derived scenario traces and behavioral deltas without external network calls.
   - Used for zero-credential local runs, unit tests, and demo workspaces.
2. **`OpenAIProvider`:**
   - Uses OpenAI API (`gpt-4o`, `gpt-4o-mini`, etc.) with `response_format={"type": "json_schema"}`.
3. **`AnthropicProvider`:**
   - Uses Anthropic Messages API (`claude-3-5-sonnet`, etc.) with structured tool use / JSON extraction.

## 4. Strict Epistemic Labeling

All output generated by the AI synthesis or static pipeline must carry one of five strict epistemic classifications:

1. **`Statically Established`**: Directly observable in the syntax tree (e.g. `param: int` changed to `param: Optional[int]`).
2. **`Framework Rule`**: Derived from documented framework contracts (e.g. DRF serializer validation order).
3. **`Inferred`**: An inductive behavioral conclusion drawn by the LLM over verified static facts.
4. **`Unresolved`**: Explicitly marked uncertainty where static analysis reaches its limit (e.g. `getattr()`, external API responses).
5. **`Runtime Verified`**: Only applicable if an actual test suite ran in an isolated test runner and produced verified pass/fail telemetry.

---

## 5. Post-Synthesis Claim Verification (Stage 11)

Every synthesized JSON response is validated before being persisted:
1. **Symbol & File Audit:** Any file or symbol cited by the model must exist in the snapshot symbol table.
2. **Edge Audit:** Any step transition in a path must correspond to a verified edge in the snapshot graph.
3. **Hallucination Rejection:** If the model cites a non-existent line number or file, the step is rejected or downgraded to `unresolved`.
